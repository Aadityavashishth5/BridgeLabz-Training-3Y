Assignment 1 – Introduction to Web Development
1. Frontend, Backend, and Full-Stack Development
Frontend development deals with the part of a website or application that users see and interact with directly in the browser. It involves HTML, CSS, and JavaScript. Example: designing the layout, buttons, and colors of an e-commerce site like Amazon.
Backend development deals with the server side of an application — the logic, database interactions, and server configuration that the user does not see. Example: processing a payment when a user checks out on Amazon.
Full-stack development combines both frontend and backend skills. A full-stack developer can build the complete application, from the user interface to the server and database. Example: a developer who builds both the visual store page and the order-processing system for a small online shop.

2. Client-Server Model Diagram
The client-server model works as follows: the client (browser) sends a request to the server, the server processes the request (often communicating with a database), and then sends a response back to the client, which displays it.
CLIENT (Browser)  →  Request (HTTP)  →  SERVER  →  Database
CLIENT (Browser)  ←  Response (HTML/CSS/JS/Data)  ←  SERVER
This request-response cycle repeats every time the user navigates to a new page or interacts with the site.

3. How a Browser Requests and Displays a Web Page
The user types a URL or clicks a link in the browser.
The browser looks up the domain's IP address using DNS (Domain Name System).
The browser sends an HTTP/HTTPS request to the web server at that IP address.
The server processes the request and sends back the requested files (HTML, CSS, JavaScript, images).
The browser's rendering engine parses the HTML and CSS to build the page layout.
JavaScript is executed to add interactivity, and the final page is displayed to the user.

4. Tools Required to Set Up a Web Development Environment
Code Editor (e.g., VS Code) – used to write and edit HTML, CSS, and JavaScript code.
Web Browser (e.g., Chrome, Firefox) – used to view and test the website, including developer tools for debugging.
Version Control System (e.g., Git) – used to track changes in code and collaborate with others.
Package Manager (e.g., npm) – used to install and manage libraries and dependencies.
Local Web Server (e.g., Live Server extension, XAMPP) – used to preview the website as it would appear when hosted online.
Terminal/Command Line – used to run commands for installing tools, managing files, and running scripts.

5. Web Servers
A web server is software (often running on dedicated hardware) that stores website files and delivers them to a client's browser when requested over HTTP or HTTPS. It listens for incoming requests, processes them, and sends back the appropriate response.
Commonly used web servers include Apache HTTP Server, Nginx, Microsoft IIS (Internet Information Services), and LiteSpeed.

6. Roles in a Web Development Project
Frontend Developer – designs and builds the user interface and user experience using HTML, CSS, and JavaScript; ensures the site looks good and works smoothly for the user.
Backend Developer – builds and maintains the server, application logic, and APIs that power the application; handles data processing and business logic.
Database Administrator (DBA) – manages the database system, ensuring data is stored securely, efficiently, and is backed up; optimizes database performance and handles data integrity.

8. Static vs Dynamic Websites
A static website displays the same fixed content to every visitor. The pages are pre-built with HTML/CSS and do not change unless a developer manually edits the code. Example: a simple personal portfolio website.
A dynamic website generates content on the fly, often based on user interaction or data from a database, so the content can change between visits or users. Example: a social media site like Facebook, where the content shown differs for each user.

9. Five Web Browsers and Their Rendering Engines
Google Chrome – uses the Blink rendering engine.
Mozilla Firefox – uses the Gecko rendering engine.
Safari – uses the WebKit rendering engine.
Microsoft Edge – uses the Blink rendering engine (based on Chromium).
Opera – uses the Blink rendering engine (also based on Chromium).
Rendering engines interpret HTML, CSS, and JavaScript to display web pages, but they can differ slightly in how they handle certain CSS properties, animations, and newer web standards, which is why a page can sometimes look or behave slightly differently across browsers.

10. Basic Web Architecture Flow Diagram
The basic web architecture flow connects the client, server, database, and APIs as follows:
1. CLIENT (Browser/App)
        ↓  sends HTTP request
2. SERVER (Web/Application Server)
        ↓  may call
3. API (Application Programming Interface)
        ↓  queries/updates
4. DATABASE (stores and returns data)
        ↑  data flows back through Server → API → Client, which displays the final result
